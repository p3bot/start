# Project: none Sentinel for --role and --context

## Goal

Replace the boolean `--no-role` flag with a value sentinel: `--role none` skips role assignment, and `--context none` drops all contexts (including required and default). A small set of case-insensitive aliases stands in for `none`. This removes the `--role`/`--no-role` flag pair whose cobra mutual-exclusion error is untyped and mismaps to exit 1, and gives contexts the same explicit "skip everything" escape hatch that role gains.

## Scope

In scope:

- Remove the `--no-role` persistent flag entirely (clean break, no alias, no deprecation shim).
- `--role <none-token>` skips role assignment, replacing `--no-role`.
- `--context <none-token>` suppresses every context: required, default, and tag/path selections.
- A single shared set of case-insensitive, whitespace-trimmed none-tokens, used identically by both flags.
- Update all references: help text, embedded help docs, examples, AGENTS.md, README.md, and tests.

Out of scope:

- Changing context resolution, required/default semantics, or the composer beyond honouring the new skip state.
- Any other flag or command behaviour.
- Re-opening decisions settled in project 02 (semantic exit codes, the fault package, the `--color` model). This project builds on 02 and reuses its `usageError` helper and exit-code taxonomy.

## Current State

This follows project 02 (`02-project-cli-contract-alignment.md`), which established the exit-code taxonomy and the `usageError`/`fault` machinery. The relevant facts:

Flag definitions live in `internal/cli/root.go`:

- `--role`/`-r` is a persistent string flag bound to `flags.Role` (root.go:124).
- `--no-role` is a persistent bool flag bound to `flags.NoRole` (root.go:133).
- `root.go:134` declares `cmd.MarkFlagsMutuallyExclusive("role", "no-role")`. A both-set violation produces cobra's untyped flag-group error, which bypasses `FlagErrorFunc` and maps to exit 1 — inconsistent with the project-02 taxonomy that classifies mutual-exclusion violations as usage (exit 2). The `--local`/`--global` pair was already migrated off `MarkFlagsMutuallyExclusive` to the explicit `validateScopeFlags` helper for exactly this reason (see `describe.go`); `role`/`no-role` was the one pair left behind.
- `PersistentPreRunE` (root.go:91-110) runs for every command, stores `flags` in context, and already resolves `--color` and derives `Debug → Verbose`. It is the natural place to normalise value sentinels into derived state.

`flags.Role` empty string already means "use the configured default role"; `flags.Context` empty slice already means "default context selection". Empty string therefore cannot double as the skip sentinel — only an explicit non-empty token may.

The `Flags` struct is in `internal/cli/start.go:35-45` (`Role string`, `Context []string`, `NoRole bool`).

`flags.NoRole` is consumed at:

- `start.go:350` (skip role resolution), `start.go:392` (compose without role).
- `task.go:123`, `task.go:305` (skip task-configured role), `task.go:374` (compose without role).

Context selection is built into `orchestration.ContextSelection` (`internal/orchestration/composer.go:18-25`) at two sites:

- `start.go:314-324`: bare `start` uses `IncludeRequired: true, IncludeDefaults: true`; the piped one-shot path uses `IncludeRequired: true, IncludeDefaults: false`. `Tags` is `flags.Context`.
- `task.go:362-365`: `IncludeRequired: true, IncludeDefaults: false`, `Tags` = resolved `flags.Context`.

`Composer.selectContexts` (composer.go) includes a context when `IncludeRequired && required`, or `IncludeDefaults && default`, or a tag matches. A selection with all three off and empty `Tags` already yields zero contexts — so "skip all contexts" is expressible as that empty selection; no composer change is required.

Audit for any additional `ContextSelection` construction site (for example in the `prompt` command path) and apply the same skip behaviour there.

Tests touching the current behaviour:

- `internal/cli/start_test.go:159` and `:206` build `Flags{NoRole: true}` directly. These stay valid — the `NoRole` field remains, now set by normalisation rather than flag binding.
- `internal/cli/start_test.go:2451` and `:2583` pass the literal `--no-role` CLI argument. These break after removal and must move to `--role none`.

Documentation referencing `--no-role`: `AGENTS.md:76` (flag table) and `:67` (`--role` row), `README.md:372` (flag table) and `:363` (`--role` row), `internal/cli/help/agents.md:21` (`start --no-role` example). Shell completion is generated by cobra from the live flag set, so removing the flag removes it from completion automatically — no completion file to hand-edit.

## Requirements

1. The `--no-role` flag is removed. Invoking it (`start --no-role`) is rejected as an unknown flag and exits 2 (usage), via the project-02 `FlagErrorFunc` path. No alias or deprecation behaviour remains.

2. A single shared none-token set is defined once and consumed by both `--role` and `--context`. Matching is case-insensitive and trims surrounding whitespace. The set is exactly: `none`, `nil`, `off`, `0`. Empty string is not a none-token.

3. `--role <none-token>` (any spelling in the set, e.g. `-r NONE`) skips role assignment, producing behaviour identical to the former `--no-role`: no role is resolved and the prompt is composed without a role, for both `start` and `start task`.

4. `--context <none-token>` suppresses all contexts — required, default, and any tag or path selections — yielding a prompt with zero contexts, for both `start` and `start task` (and any other context-composing command path).

5. Mixing a none-token with real selectors in `--context` (for example `--context none,project` or `-c none -c project`) is a usage error (exit 2) with a message naming the conflict. A none-token must be the sole context selector.

6. Normalisation is centralised so downstream code is not duplicated: the none-token decision is made once per invocation and existing consumers of the skip state (`flags.NoRole` and its context equivalent) continue to drive role-skipping and context-skipping without per-call-site token parsing.

7. All documentation and examples reflect the new model: the `--no-role` row is removed from the flag tables, the `--role` description notes that `none` skips role assignment, a `--context` note documents that `none` drops all contexts, and the `start --no-role` example becomes `start --role none`. List the none-token aliases in user-facing help.

8. Test coverage proves: role-skip via `none` and via at least one alias and a mixed-case spelling; context-skip via `none` removes a required context that would otherwise be injected; the `--context` mixing case returns exit 2; and `--no-role` now returns exit 2. Existing direct-field `Flags{NoRole: true}` tests still pass unchanged.

## Constraints

- Go; build with `go build ./...`; the full pipeline is `scripts/invoke-tests`. Reuse the project-02 `usageError` helper for exit-2 classification rather than introducing a new error path.
- `flags.Role == ""` and an empty `flags.Context` must keep their current meanings (default role, default context selection). Do not let normalisation alter the no-flag-given behaviour.
- Clean break, consistent with project 02's removal of `--no-color` and `--yes`: remove every internal reference to `--no-role`, not just the flag registration.
- Do not reintroduce `MarkFlagsMutuallyExclusive` for role. With `--no-role` gone there is no pair to exclude; the mutual-exclusion defect must not reappear in another form.

## Implementation Plan

1. Define the none-token set and a single predicate that reports whether a trimmed, case-folded string is a none-token. Place it where both root-level normalisation and any flag-specific validation can reach it.

2. In `root.go`, remove the `--no-role` flag registration and the `MarkFlagsMutuallyExclusive("role", "no-role")` line. Update the `--role` flag description to mention that `none` skips role assignment.

3. In `PersistentPreRunE`, after the existing flag-context and colour handling, normalise both flags:
   - If `flags.Role` is a none-token, set the derived role-skip state and clear `flags.Role` so downstream default-role logic does not also fire.
   - If any element of `flags.Context` is a none-token, set the derived context-skip state. If a none-token is mixed with other selectors, return `usageError` (Requirement 5). On skip, clear `flags.Context` so no stale selectors leak through.

   A derived context-skip field on `Flags` (mirroring how `NoRole` already works as derived state) keeps the two context-selection sites simple. Example shape, not prescriptive:

   ```
   if isNoneToken(flags.Role) { flags.NoRole = true; flags.Role = "" }
   // context: detect none-token(s), reject mixes, set flags.NoContext, clear flags.Context
   ```

4. At each `ContextSelection` construction site (`start.go`, `task.go`, and any other found in the audit), when the context-skip state is set, build the selection with `IncludeRequired`, `IncludeDefaults` both false and empty `Tags`, so the composer emits no contexts. Leave the composer untouched.

5. Update the debug strings that mention `--no-role` (start.go:393, task.go:374) to reflect the new spelling.

6. Update docs: `AGENTS.md`, `README.md`, and `internal/cli/help/agents.md` per Requirement 7.

7. Update and add tests per Requirement 8. Convert the two `--no-role` CLI-argument tests to `--role none`.

## Implementation Guidance

- Every none-token is a reserved value: a role or context tag literally named `none`, `nil`, `off`, or `0` becomes unreachable through its flag. This is an accepted trade — names are kebab-case identifiers where these tokens are implausible — but keep the set small and do not expand it without cause.
- Check the none-token before any path or name resolution, so the sentinel is matched as a bare value and a file path such as `./none.md` is never mistaken for the sentinel.
- Prefer normalising once in `PersistentPreRunE` over scattering token checks across role and context resolution; the derived `NoRole`/`NoContext` state is the seam the rest of the code already understands (role) or should mirror (context).
- The `--role`/`--context` skip and the `--context` mixing error are usage-domain outcomes; route them through the same `usageError` path project 02 established so exit codes stay consistent.

## Acceptance Criteria

- `start --no-role` exits 2 (unknown flag); the flag no longer appears in `start --help` or generated completions.
- `start --role none`, `-r NONE`, `--role nil`, `--role off`, and `--role 0` all run without a role, matching the former `--no-role` behaviour, for both `start` and `start task`.
- `start --context none` (and each alias) produces a prompt containing no contexts, including a context marked `required: true` that bare `start` would otherwise inject.
- `start --context none,<real>` exits 2 with a message naming the conflict.
- `start` with no `--role` and no `--context` is unchanged: default role resolves and the default/required context selection is injected.
- No occurrence of `--no-role` or `no-role` remains in non-test source, help docs, AGENTS.md, or README.md.
